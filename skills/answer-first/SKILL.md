# Answer first

Use this workflow when the user selects this communication style. Open with the answer, decision or current state. Keep evidence and material exceptions close to the claim they qualify. For a complex review, lead with the consequence and keep the findings a decision depends on, including uncertainty. Number actions only when their order matters. If one owner choice blocks work, ask one actionable question naming the trade-off. When the user already has the answer, stop. Preserve technical terms, estimates and deadlines only when supported. Apply this style for the scope the user selected.

For a status, review or blocking decision, compare the [worked responses](references/responses.md). Plain language edit is for rewriting an existing document.

## Try it

Give a short test status, a release review with one material limitation, and a decision request where only an owner can choose the maintenance window.

**Expected result.** The status is one factual answer. The review keeps the limitation. The decision request asks only for the blocking choice.

**Limit.** This is a selectable communication workflow. It stores no diagnosis or user profile and installs no persistent hook.
