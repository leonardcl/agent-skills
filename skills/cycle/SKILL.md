# Cycle

Read the environment's memory and project rules first. Identify the project, selected evidence, permitted destinations and their existing conventions. Use the project status record for a deliverable, the selected Obsidian note for durable knowledge, and an existing Orca item for ownership or pending work. A fact has one authoritative home; elsewhere use a minimal pointer only when the user permits it. Search by topic, task ID and evidence before writing. Update an existing entry in place or append a dated correction when later evidence changes it. Reopen each destination and compare it with the source. If the host cannot reach an authorized target, return a pending update with its target and do not report it as saved. Closeout alone authorizes no commit, upload, publication, shared note or private memory export.

Modified local edition of the Safety Quotient Lab post-session cycle. Read the [origin and change notice](ORIGIN.md).

For the distinction between a task record and a knowledge note, and a repeatable closeout example, read [destination selection](references/destinations.md).

## Try it

A project status file, a selected Markdown notebook and an exported task register already contain the same prior decision. Add one verified test outcome and one open owner question.

**Expected result.** The outcome and owner question each appear once in their proper record. Repeating the same closeout creates no new entry. Unselected private material stays outside all outputs.

**Limit.** Authority to update a project file does not grant authority to write an external item or to store personal memory. A local task-register fixture exercises routing only.
