# Task routing

Choose an execution path for a request with several plausible deliverables.

## Workflow

Identify what the user wants to have at the end. A diagnosis ends at an evidenced cause, a comparison at a decision, and a repair at an exercised change. Use the supplied scope to select that finish line.

Resolve factual forks with the cheapest discriminating observation. For “search is slow,” time the same query against the same data and see whether the delay is in fetching or displaying results. If the decision depends on an unknown preference, ask about the specific trade-off. Keep changes that depend on the observation sequential. Finish when the requested outcome can be demonstrated, or name the exact missing input.

## Try it

Someone asks to improve search but supplies only a slow search example.

**Expected result.** A scoped route with a baseline measurement, an explicit change boundary and a completion check.

A slow query supplies a symptom. Record one query and dataset size, measure its current latency and establish whether the request ends at diagnosis or includes a patch.

**Limit.** An ambiguous goal can justify one focused question.
